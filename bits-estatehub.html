What it is

Bits EstateHub runs a flat-sales business from one place: projects and flats, customers, allotments, payments, instalments, construction progress and sales-team performance.

User interface

Dashboard

Receivables for this month and next, the sales team, overdue instalments, construction progress by project, and money totals with thousand separators.

Sidebar navigation

Dashboard, Projects & Flats, Customers, Allotments, Payments, Reports, Investment Movements, Administration, Import Excel, Backups, Audit Trail and About.

Customer 360

One screen per customer: flats, payment schedule, payment history, and the Print and PDF buttons.

One colour theme

The same navy, blue and amber across every page.

Works in any modern browser on the office network. Other devices on the same network connect through the server's address.

How easy it is to use

  • Forms ask for one thing at a time, and mistakes are explained in plain words.
  • Customer statements and reports are produced with one click.
  • Monthly instalments in one step: enter the balance and the number of months. The app splits it into equal instalments, and the last one absorbs rounding, so the total always matches exactly.
  • Every amount stays editable. A customer who pays more or less than the scheduled figure is handled without rebuilding the schedule.
  • Excel import shows a preview before anything is saved.
  • Administrators decide who can view, add or change data, by role.

Printing and PDF

  • Branded A4 PDFs for the customer payment statement, the Project & Payment Update letter, payment receipts, and sales and project reports.
  • Save as PDF: every document downloads as a PDF file.
  • Print: the receipt page has a Print button that opens the computer's print dialog. Choose any printer installed on the PC, or choose “Save as PDF”.
  • Printed pages hide the menus and buttons automatically.
  • Reports are also available as Excel (.xlsx). The property report also exports to CSV.

Backup

Offline backup (local) Available

  • Administration → Backups creates a full database backup with one click.
  • SQL Server makes the backup itself and checks it before it is listed.
  • Backups are stored on the SQL Server computer, in SQL Server's backup folder.
  • Keep a copy on another drive or a USB device for safety.

Google Drive backup Planned

Not yet built. Until it is added, backups stay on the local computer.

Restore Planned

The app cannot restore a backup yet. A restore is currently done in SQL Server Management Studio.

Import

  • Import flats and customers from Excel (.xlsx / .xlsm, up to 10 MB).
  • The app checks the column headers, shows a preview, and imports only after you confirm.
  • Other import formats (CSV, other layouts) are not supported yet.

Security

  • Passwords are stored as secure hashes (PBKDF2, 200,000 iterations).
  • Five wrong login attempts lock the account for 10 minutes.
  • Every change is recorded in the Audit Trail: who, what, when, and from which machine.
  • Owner recovery: a one-time recovery code, created by an administrator, lets the owner reset an administrator password if every administrator is locked out. Vendor-assisted recovery is planned.

Technology

Python (Flask) web application, SQL Server Express database, and the Waitress server on Windows. It runs on the office network with no monthly subscription.

Known limits

  • Google Drive backup, restore, reset, and the role-permission editor are planned, not available yet.
  • The screen styles load from the internet. On a computer with no internet access the layout may look plain until the styles are stored locally. This is planned.
